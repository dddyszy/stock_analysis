# 迭代计划

本计划从当前版本的回测结论出发，按「先证明有没有用，再决定怎么用」的顺序排优先级。每个阶段都写明完成标准和决策点：做不到就调整方向，而不是继续叠加功能。

---

## 一、现状（v0.3，`dev` 分支）

### 已具备的能力

- **数据**：沪深 5018 只股票、近 5 年前复权日线（约 293 万根）；腾讯评分、估值、风险标签全市场覆盖；候选股三大报表按需补拉、缓存 20 天。
- **缠论引擎**：包含处理 → 分型 → 笔 → 线段 → 中枢 → 走势类型 → 多指标背驰 → 笔级别与线段级别的一二三类买卖点；日线、周线联立。
- **选股**：基本面与风险过滤、流动性过滤、缠论打分、主推荐 / 观察池分流、按大盘状态降级。
- **持仓**：按风险反推仓位、分层止损、跟踪止损、分批止盈、状态机；腾讯模拟盘下单与对账；写回 App 自选分组和股价提醒。
- **验证**：逐根推进的无未来函数回测、随机对照组、同市场状态加权比较、分维度诊断、逐年滚动检验、出场规则实验；推荐跟踪看板（前瞻数据）。

### 关键结论（1000 只股票、约 4 年、1126 笔信号交易）

| 问题 | 结论 |
| --- | --- |
| 缠论买点是否跑赢随机入场？ | 否。同市场状态下优势 +0.01～+0.09 R，置信区间都跨过 0 |
| 能否从历史里学出「只做某些组合」的规则？ | 不稳定。逐年滚动检验合计优势 +0.03 R，2025 年挑出的组合反而跑输 |
| 有没有稳定跑输的情况？ | 有：周线共振向上时入场（4 年里 3 年更差）、大盘上涨期的一买、大盘下跌期的三买。已据此调整规则 |
| 调整出场规则能否改善？ | 否。5 组出场规则相对随机组的优势都接近 0 |
| 线段级别信号是否可用？ | 4 年只产生 2 笔交易：止损太宽，被「止损距离过大就跳过」拦掉 |

### 已知局限

1. **幸存者偏差**：回测只能用当前在市的股票。
2. **没有历史快照**：基本面、风险标签只有当前数据，无法在回测里检验这些过滤是否有效。
3. **成交额靠估算**：公开接口的历史日线没有成交额，只能用成交量 × 收盘价估算。
4. **风险标签口径粗**：「经营现金流为负」覆盖约 44% 的股票。
5. **MCP 限频**：财报补拉经常被限频，每天两次以上的全量流水线会互相抢配额。

## 二、版本规划

### v0.4 · 数据积累与运维加固（约 2 周）

目标：从今天开始积累能用于未来回测的「当时数据」，同时让每天的自动流程不再需要人盯着。

| 事项 | 内容 | 完成标准 |
| --- | --- | --- |
| 每日快照 | 每天收盘后保存股票池（含 ST、停牌、行业）、风险标签、估值和腾讯评分的快照，按日期存储 | 连续 10 个交易日无缺失；回测能按日期读取当时的快照 |
| 退市股记录 | 股票池刷新时，把消失的股票标记为退市并保留其历史数据 | 新退市的股票在回测抽样池中仍可见 |
| 风险标签校准 | 统计每个扣分标签在推荐跟踪里的实际表现；覆盖面过大的标签（经营现金流为负）改为只提示或按连续多期判断 | 每个扣分标签都有「有 / 无该标签」的后续收益对比 |
| 自动检查 | GitHub Actions：每次提交跑后端测试和前端构建 | `dev` 分支提交后自动检查通过 |
| 失败提醒 | 收盘后流水线失败、超时、授权失效时，通过企业微信或邮件通知 | 人为制造一次失败能收到提醒 |
| 清理推荐分组 | 已不再推荐的股票从「缠论推荐」分组移出的规则更清晰，保留用户在其他分组里的股票 | 分组里只剩当前主推荐和用户手动加入的股票 |
| MCP 配额管理 | 同一天内重复运行流水线时，已经拉过的财报直接用缓存；限频冷却期间暂停其他可选调用 | 手动重跑流水线时财报步骤在 1 分钟内完成 |

### v0.5 · 入场质量研究（约 3～4 周）

目标：找到**在逐年滚动检验中仍显著跑赢随机组**的入场条件。这是整个系统能否作为选股工具的关键。

每个候选因子都走同一套流程：加进回测 `tags` → 看「信号诊断」→ 看「逐年滚动检验」→ 两者都显著才纳入选股规则。

| 研究方向 | 假设 | 做法 |
| --- | --- | --- |
| 相对强弱 | 买点出现时个股强于大盘、强于行业，成功率更高 | 标记入场前 20 / 60 日相对中证 1000 和所属行业的超额 |
| 量能确认 | 离开中枢时放量、回抽时缩量的三买更可靠 | 标记突破段与回抽段的量比 |
| 背驰参数敏感性 | 当前背驰阈值可能过松 | 对面积比、DIF 比等阈值做网格实验，只看滚动检验结果 |
| 线段级别信号可交易化 | 线段买点方向更可靠，但止损太宽 | 用笔级别结构做止损、线段级别做方向过滤，比较结果 |
| 区间套（次级别确认） | 日线买点叠加 30 分钟级别的买点确认，入场更精确 | 先确认数据源：公开接口只有近期分钟线，需要评估能否长期积累 |
| 行业与市值分层 | 缠论在高波动小盘股和低波动大盘股上的表现可能不同 | 在诊断里增加市值分组和行业分组 |

**决策点**：
- 如果找到一个或多个组合，在 1000 只以上的样本上逐年滚动检验显著为正，并且推荐跟踪的前瞻数据方向一致，就把它们作为主推荐的必要条件，进入 v0.6。
- 如果都找不到，就把系统定位调整为「结构分析 + 风控工具」：推荐页改名为「结构候选」，重点放在持仓管理和风险提示上，停止以超额收益为目标的调参。

### v0.6 · 组合层面（约 2～3 周）

目标：从「单笔交易的平均 R」升级到「整个账户的净值表现」。

| 事项 | 内容 |
| --- | --- |
| 组合级回测 | 按真实资金、单笔 1% 风险、单只 20% 上限、市场温度仓位上限、最多同时持仓数模拟整条净值曲线 |
| 组合指标 | 年化收益、年化超额、最大回撤、夏普比率、卡玛比率、换手率、手续费占比 |
| 行业集中度 | 主推荐和持仓限制同一行业的数量或权重 |
| 相关性控制 | 新开仓时考虑与已有持仓的相关性，避免同涨同跌 |
| 仓位上限验证 | 回测市场温度对应的仓位上限是否真的降低了回撤 |

**完成标准**：组合回测的最大回撤和超额收益都优于「等权买入中证 1000」基准；否则回到 v0.5 的结论重新评估。

### v0.7 · 使用体验（约 2 周）

| 事项 | 内容 |
| --- | --- |
| 每日报告 | 收盘后生成一页摘要（市场温度、新增推荐、持仓建议、预警），推送到企业微信或邮件 |
| 移动端适配 | 主要页面在手机浏览器上可读 |
| 复盘笔记 | 每笔交易可以记录买入理由和复盘结论，和持仓计划关联 |
| 配置对比 | 在回测页直接比较两套策略配置 |
| 安全配置 | 数据库密码从代码默认值中移除，只从 `.env` 读取；敏感配置不进入仓库 |

## 三、持续进行的事项

- **推荐跟踪**：每周看一次，重点关注 Rank IC 和相对中证 1000 的超额。连续 4 周 IC 小于 0 时暂停写回 App，并排查原因。
- **回测复核**：每次修改缠论规则或选股参数后，都要跑一次 1000 只股票的回测，并对比修改前后的「信号诊断」和「逐年滚动检验」。
- **规范维护**：新增的数据口径、验证方法都写进 `AGENTS.md`。

---

## 四、暂不考虑

| 事项 | 原因 |
| --- | --- |
| 实盘自动下单 | 在没有证明信号优势之前，自动化只会放大风险 |
| 北交所、港股、美股 | 先把沪深做扎实；北交所历史数据在公开接口上也拿不到 |
| 机器学习选股 | 当前样本量下极易过拟合，先用可解释的规则把验证框架跑通 |
| 更高频（分钟级）交易 | 数据源限频严重，且与缠论日线 / 周线的定位不符 |
